# Decision Log

Architectural and design decisions for the LibrePod marketplace. One row per
decision; keep each rationale to a sentence or two — this log records *what* and
*why*, not a full analysis (detail lives in code comments, troubleshooting docs,
or a dedicated write-up when a decision needs one).

Append-only: add a new dated row for each decision. If a decision is reversed,
mark the old row **Superseded by #N** and add the replacement — don't delete or
rewrite history.

| # | Date | Area | Decision | Rationale |
|---|------|------|----------|-----------|
| 1 | standing | packaging | Apps are packaged as OCI artifacts and deployed via FluxCD GitOps | Git-first, immutable, signed artifacts; cluster state is derived from git rather than mutated in place. |
| 2 | standing | networking | Apps expose HTTP through Traefik `IngressRoute`s; TLS is centralized in Traefik's default cert store — apps do not declare `tls:` blocks | One place for cert management; app manifests stay minimal. |
| 3 | standing | isolation | Each app creates and owns its namespace (named after the app) | Self-contained apps with a clear blast radius. |
| 4 | 2026-07-28 | cross-cutting | Host (NixOS) changes stay minimal or none; all app routing/NAT lives in the app + Kubernetes. The only exception is opening UDP 51820 on the host firewall (wg-easy is the device entrypoint) | Keeps the OS generic and makes every app portable across any device, NIC name, or network. |
| 5 | 2026-07-28 | wg-easy | Run without `hostNetwork`; expose on-LAN WireGuard UDP 51820 via a Traefik entryPoint; add a `sysctl` initContainer (`net.ipv4.ip_forward`, `net.ipv4.conf.all.src_valid_mark`) | Under `hostNetwork`, wg-easy's MASQUERADE landed on a wrong/guessed interface in a non-deterministic firewall backend (nftables vs legacy iptables), breaking NAT on some identical hosts. A pod netns always has `eth0`, so NAT is deterministic; routing through Traefik centralizes ingress and keeps the pod portable. Remote access uses the FRP relay → the wg-easy ClusterIP Service (no Traefik). |
| 6 | 2026-08-18 | marketplace-ui | **Superseded by row 8.** Gate `marketplace-ui` on the `user-apps` Flux Kustomization via `dependsOn` (not on a Gogs-specific readiness probe); delete the `wait-for-gogs-user` initContainer (issue #180) | The first install on a cold cluster 500'd because the server could become Ready while `flux/user-apps` was still commitless — a PUT to a commitless repo returns Gogs 500 (live-verified). `user-apps` Kustomization Ready ⇔ Flux cloned a seeded repo and applied it, which is provider-neutral (same meaning for Gogs, GitHub, or GitLab) — the true installer invariant. The deleted initContainer only polled a Gogs-only endpoint and gated on the flux *user*, never the seeded *repo*, so it was redundant and backend-coupled. The two prior fixes (#176/#177) targeted the token and failed; auth was never the problem. Server 503-robustness (#181) and per-app Kustomizations (#182) are follow-ups. |
| 7 | 2026-08-22 | marketplace-ui | Git operations on the `flux/user-apps` repo go over **HTTP(S), not SSH**: `GitRepository/user-apps-source` clones `http://gogs.gogs.svc.cluster.local.:80/flux/user-apps.git` with `Secret/user-apps-source-auth`, and the marketplace-ui installer writes over the same transport (an `ssh://` remote is rejected at resolution, not silently attempted). Reverses the SSH switch made in #50, which predates this log (issue #182) | One transport, and it is the one the hermetic test tier actually exercises: Tier 1's Gogs has no port 22, so the HTTP path had to exist regardless and SSH would have shipped as the only transport no fast test covers. #50's "no baked-in credential" rationale no longer holds — the `flux` password is a committed literal reflected into two namespaces, so the keypair bought ceremony rather than secrecy, at a cost of ~80 lines of bootstrap shell and `openssh-client` in the app image. HTTP can also use the absolute (trailing-dot) hostname the installer needs, which SSH cannot without re-keying `known_hosts` since host keys bind to the exact name given. `apps/gogs` needs no change: smart-HTTP git is already enabled there and already grants this credential read *and* write (live-probed). Accepted trade-off: basic auth crosses the pod network in plaintext — cluster-internal, single-node appliance, and the credential is already public — revisit in-cluster TLS or SSH when that credential is rotated. Every claim here was checked against the pinned Gogs build and a live cluster rather than assumed — smart-HTTP git already enabled, this credential already granted read *and* write, and the contents API's absent DELETE route; probe details in issue #182. |
| 8 | 2026-08-22 | marketplace-ui | Split the app-store wiring into three Flux layers with distinct meanings — `user-apps-source` (Ready ⇔ a selective healthCheck on GitRepository/user-apps-source, i.e. the git source is seeded), `user-apps` (`wait: false`, apply-only), `marketplace-<app>` (`wait: true`, that app's health) — gate `marketplace-ui` on the first; drop the shared root `kustomization.yaml` in favour of Flux's auto-generated one; and perform every repo mutation with a generic git client instead of the provider's REST API (issue #182) | `user-apps` with `wait: true` health-checked every per-app Kustomization it applied, so ONE unhealthy app turned the shared object `Ready=False` and, via #180's gate, could block re-applying the installer UI — the tool needed to remove it. Apps already had their own Kustomizations, so the fix was to dissolve the aggregate, not to redesign installs. The root file was also a shared mutable allow-list serialising every install; removing it makes install/uninstall one atomic commit each and retires the "Pitfall 3" write-ordering rule. The git client is required, not preferred: this Gogs release has NO DELETE route on its contents API (live-probed), so uninstall could never delete an app's files over REST — and git is what makes the repo pluggable to GitHub or GitLab. Note this buys HEALTH isolation, not build isolation: with the whole tree as the build input, one malformed YAML file still fails the build for every app. |
