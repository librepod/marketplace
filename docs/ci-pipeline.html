How a merge becomes a release

Two kinds of things ship from this repo. The products we build ourselves get a version from their release workflow and nowhere else. App artifacts for upstream software publish on every merge.

01 · Our own products

publish-<product> builds, a release workflow versions

Same shape for all three products: publish-<product> never writes a version, and a release workflow (release-self-built for the two apps, release-bootstrap) is the only writer of :X.Y.Z and of the <product>-vX.Y.Z git tag, which lands on the master commit once the artifacts are signed. Bootstrap has no release PR because its version lives only in git tags. A release PR also bumps infrastructure/system-apps/<app>.yaml, so its merge fires publish-bootstrap too, and the next bootstrap release carries the new pin.
